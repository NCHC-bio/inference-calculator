## 1. TP 下 GQA 的 KV heads：每個 rank 持有幾個

| 1.4 | 啟動時的全域檢查：`total_num_attention_heads % tensor_parallel_size != 0` 會丟 `ValueError`。 | 〔code〕 | [config/model.py#L1544-L1551](https://github.com/vllm-project/vllm/blob/5df63a7203cdb9328d824a27b682e77c7b9928be/vllm/config/model.py#L1544-L1551) |
| 1.5 | KV cache spec 的 `num_kv_heads` 取自上述 per-rank 值，每個 token、每層的 bytes 為 `num_kv_heads × (head_size + head_size_v) × dtype_size`，每個 block 再乘 `block_size`。 | 〔code〕 | [attention.py#L669-L677](https://github.com/vllm-project/vllm/blob/5df63a7203cdb9328d824a27b682e77c7b9928be/vllm/model_executor/layers/attention/attention.py#L669-L677)、[kv_cache_interface.py#L544-L553](https://github.com/vllm-project/vllm/blob/5df63a7203cdb9328d824a27b682e77c7b9928be/vllm/v1/kv_cache_interface.py#L544-L553) |
| 1.6 | 官方文件說明：TP 超過 H（KV heads 數）時，「the KV cache for each GPU will be duplicated for `tp_size / H` times」。可以用 `-dcp`（decode context parallel）沿 token 維度再切，範圍是 `[1, tp_size/H]`。 | 〔docs〕 | [context_parallel_deployment.md#L32-L38](https://github.com/vllm-project/vllm/blob/5df63a7203cdb9328d824a27b682e77c7b9928be/docs/serving/context_parallel_deployment.md#L32-L38) |
| 1.7 | **V0 時代規則相同**：v0.6.0 的 `get_num_kv_heads` 也是 `max(1, total_num_kv_heads // tp)`。 | 〔code〕 | [v0.6.0 config.py#L516-L524](https://github.com/vllm-project/vllm/blob/32e7db25365415841ebc7c4215851743fbb1bad1/vllm/config.py#L516-L524) |

**結論**：

- per-rank KV heads = `max(1, K // tp)`。
- 整個 replica 的 KV 總量 = `tp × per-rank` = **`max(K, tp)` × 單 head 的 KV**，前提是通過可整除檢查。
  - K ≥ tp：恰好是 K，沒有浪費。
  - K < tp：變成 tp，等於複製了 `tp/K` 份。
- **可整除規則**：
  - `num_attention_heads % tp == 0`（全域檢查）。
  - KV heads：`K % tp == 0`（K ≥ tp）或 `tp % K == 0`（K < tp）（模型層 assert）。

**結論（對計算機）**：

- InferenceX 的 gpt-oss 點跑的是**非預設**的 Marlin kernel；v0.32.0 在 H100／H200 的預設是 OAI Triton。每個點的 `conditions.deviations` 都寫了這件事。
- Ruling R41 採用的 `tFixedSec` 是由 dense FP8（Llama，沒有 MoE kernel）與 MXFP4（gpt-oss，Marlin）兩個 fit 點共同擬合、與格式無關的每步開銷，不是 Marlin 專屬的效率。所以驗證指令**維持 v0.32.0 的預設 kernel**（國網使用者實際會部署的設定），並在 MXFP4 的原生 checkpoint 註解寫明：校正點是以 Marlin 量測的，要和校正點比對時加 `--moe-backend marlin`。
- 待國網量測（issue #10）：同一條件下 `--moe-backend auto` 與 `marlin` 各量一次，確認 MoE kernel 對 decode 與 TTFT 的影響。

## 對計算機的影響

以下記號：

- L_g：layer group g 的層數（若有 PP，指單一 stage 的層數）。
- K_g：KV heads 數。
- d_g：head_dim。
- b_kv：KV dtype 的 bytes。
- tp：TP 大小。

1. **GQA／MHA 的 per-rank KV**（每 token）= Σ_g `max(1, K_g // tp)` × 2 × d_g × b_kv × L_g。
   - **每個 replica 的 KV 總量** = Σ_g **`max(K_g, tp)`** × 2 × d_g × b_kv × L_g。
   - 規則**逐 layer group 套用**，例如 Gemma 4 的 global 層 K=4 會在 TP=8 時複製，sliding 層 K=16 不會。（§1、§3.6）
2. **可整除檢查**要做成前置驗證，不符合就標為不可行：
   - `heads % tp == 0`。
   - `K_g % tp == 0` 或 `tp % K_g == 0`，逐 group 檢查。（§1.3–1.4）
3. **MLA 的 per-rank KV** = (kv_lora_rank + qk_rope_head_dim) × b_kv × L，**沒有 ×2**。
   - **每個 replica 的 KV 總量 = tp × latent**；啟用 DCP=d 時為 (tp/d) × latent。
   - MLA 模型忽略 config 的 `num_key_value_heads`。
   - Mistral Small 4：23,040 B/token/rank（BF16）。（§2）
4. **Sliding window 層**（hybrid manager 開啟時，也就是 GPU 上的預設）：分清楚**上限**與**穩態**（2026-10-20 更正：原本把上限當成每人用量）。
   - **穩態**（容量用這個）：每個常駐 request 每個 SW 層 `min(window, 上下文)` 個 token，以整塊計時平均 `min(ceil(上下文/bs)·bs, window + bs − 1)`（§3.13），因為 window 外的 block 在每個 chunk 配置前就釋放（§3.11）。
   - **暫態**：進行中的 chunk 會暫時超出 window，全部 request 合計每步最多 `max_in_flight_tokens = max_concurrent_batches × max_num_batched_tokens`（預設 async scheduling、PP = 1：2 × max_num_batched_tokens，§3.12）。計算機在每個副本**只扣一次** `min(max_in_flight_tokens, 上下文)` 個 token 的 SW 層 KV（上下文 ≤ window 時為 0，因為沒有東西會被釋放），不是每人都扣。
   - **上限**（啟動檢查用）：每個 request `min(window − 1 + max_in_flight_tokens, max_model_len)` 個 token 再加 1 個 block（§3.3）。可用 KV 記憶體放不下 1 個 request 的上限（full 層 max_model_len + SW 層上限）時，vLLM 拒絕啟動（§3.11），計算機標為記憶體不足。啟動日誌的「Maximum concurrency」也用上限算，所以會**低估**穩態可服務的人數。
   - 若 hybrid manager 被關閉（例如使用某些 KV connector），SW 層改以 `max_model_len` 計。（§3.3、§3.5、§3.11、§3.12）
5. **每個 rank 的 KV 可用記憶體** = `ceil(cudaTotal × util)` − 權重 − activation 峰值 − 非 torch − CUDA graph。
   - util 預設 **0.92**。
   - cudaTotal 用 `mem_get_info` 的 total，不是 nvidia-smi 的值。
   - 扣除項目前標為 estimate，應以實測的「Available KV cache memory」校正。（§5）
6. **併發上限** = min(`max_num_seqs`, KV block 數 ÷ 每個 request 的 block 數)。
   - `max_num_seqs` 預設：H100／H200 為 1024，A100 為 256，以**每個 DP rank** 計。
   - benchmark 的 `--max-concurrency` 超過上限時，超出部分計入 TTFT 排隊時間。（§7）
7. **權重 bytes**：embedding 與 lm_head 以 BF16 計，除非 checkpoint 明確量化它們（AWQ 的 `lm_head: true`，或 compressed-tensors 的 targets 涵蓋 lm_head）。
   - 線上 FP8、AWQ、compressed-tensors FP8：attention 投影與 MLP／experts 以量化 bytes 計。
   - **gpt-oss MXFP4**：只有 MoE experts 是 4-bit，attention、router、embedding、lm_head 都是 BF16。（§4）
8. **`max_model_len`** 超過 config 推得的上限時，標為「vLLM 會拒絕啟動」，除非設定 `VLLM_ALLOW_LONG_MAX_MODEL_LEN=1`，但這有正確性風險。（§6）
9. **N 個 replica**：
   - 建議指令：`--data-parallel-size N`，單一 endpoint，benchmark 打單一 `--port`。
   - dense 模型也可以跑 N 個獨立 process，各自設定 `CUDA_VISIBLE_DEVICES` 與 `--port`。
   - 每個 replica 的 KV、`max_num_seqs` 都獨立計算。（§8）
10. **gpt-oss MXFP4 MoE kernel**：v0.32.0 在 Hopper 預設 OAI Triton；`VLLM_MXFP4_USE_MARLIN` 已移除，改用 `--moe-backend marlin`。驗證指令用預設 kernel，註解說明校正點是 Marlin。（§9）
