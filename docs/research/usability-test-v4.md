# 可用性測試：草稿 v4（模擬使用者 think-aloud）

- **日期**：2026-10-19
- **方法**：
  - 5 個 Agent 各自扮演一種使用者，以無頭瀏覽器（Edge）操作 v4 草稿，透過截圖觀看畫面，同時把想法說出來（think-aloud）。
  - **不允許閱讀原始碼。**
  - 每個問題都標示嚴重度，並引用當時畫面上的原文。
  - 頁面中給設計者看的設計依據說明已先移除。
- **截圖位置**：`scratchpad/uitest/p1`～`p5`（暫存，不納入版本控制）
- **限制**：這是模擬使用者，不能取代真人測試。發現的問題適合當作假說，正式版仍應找國網的真實使用者測試。

## 做得好的地方（應保留）

- **答案句的介面**：每個人都說「很快看懂」「像在跟我對話」（P1 P3 P4）。
- **打字示範讓不懂 tok/s 的人理解速度**：P1 說「原來 59 tok/s 就是這種速度，夠快了」。
- **誠實標示推估**：P3、P4 都認為這比一般計算機強，前提是措辭要專業、要能點開看依據。
- **瓶頸使用率條**：P3 可以用 roofline 直覺自行核對；P4 認為方向正確。
- **機器圖示用來計數**：P5「一眼就看懂是 2 台」。
- **把 KV cache 拆開計算**：P4 認為比只算權重的計算機強。

## 從使用者角度看到的閱讀模式

1. **大家先讀答案句，再讀結論那一行，並把結論行當成「唯一答案」。** 結論行沒寫的東西（保守數字、比較標準），使用者就當作不存在。
2. **每一列的文字比圖示更常被讀。** 圖示只用來計數；高度、填色、殘影這些編碼幾乎沒人用。
3. **使用者真正要的單位是「人」和「字」**，不是 GB 或 tok/s。「可容納上限 N 人」是最受重視的資訊。
4. **使用者最後的產出是一段要交給別人的文字**（申請書、校長報告、長官簡報）。所以結果必須能被引用，而引用的前提是能追溯出處、措辭專業。
5. **不同角色的入口不同**：有人從總人數出發，有人從手上的硬體出發，有人從模型出發。單一入口（只能填同時人數）會讓其中幾種人卡住。
