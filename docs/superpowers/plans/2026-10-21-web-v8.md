# 網站 v8 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把使用者核可的 demo v8 做成 `packages/web` 的正式網站：沒有模式切換，每列可調卡數，展開後是單一畫面的試算區，並提供自訂硬體／模型／工作／速度、漏斗、依據、引用、分享、比較、驗證指令與準確度。數字全部來自 core。

**Architecture:** 沿用第二階段結構（集中 reducer store + URL、`compute/` 呼叫 core、`i18n/`、antd + D3）。state 改成 v8 形狀；`compute/` 新增每列效能、試算區資料與建議動作；元件依 demo 重寫成 `Collapse` 列表與試算區。所有新的 core 呼叫來自 `2026-10-21-core-v8.md`（必須先完成）。

**Tech Stack:** React 19.3.0、antd 6.6.5、@ant-design/icons 6.3.4、d3-selection 3.0.0、d3-transition 3.0.1、d3-scale 4.0.2、Vite 8.3.3、Vitest 5、Testing Library、Playwright 1.63.0（全部沿用 `packages/web/package.json` 現有版本；新增依賴只有 workspace 的 `@nchc/data`，用於 `@nchc/data/hf`）。

**Spec:** `docs/superpowers/specs/2026-10-21-direct-manipulation-design.md`（下稱「設計」）；視覺規格 `docs/prototypes/calculator-demo-v8.html`（下稱「demo」，commit `6e00bce`）；core 計畫 `docs/superpowers/plans/2026-10-21-core-v8.md`。

## Global Constraints

- 網站不得自己實作公式、不得出現硬體／模型／工作數值（測試 fixture 例外）；數字只來自 core 回傳值與 bundle。
- `src/bundle.ts` 是 `bundle.json` 唯一匯入點；`src/accuracy.ts` 是 `accuracy.json` 唯一匯入點。
- 只有 `CoreInputError` 變成畫面上的錯誤；其他 Error 往上拋給 `ErrorBoundary`。
- 版面與文案照 demo；設計 §3 的每一條準則都適用（hover popover 維持 hover、長內容在 Drawer、依據與引用是 Modal、`Collapse`、只用 `@ant-design/icons`、Mac 灰色、不溢出、所有變化有過渡）。
- motion token：`TRANSITION_MS = 400`、`EASE = 'cubic-bezier(0.215, 0.61, 0.355, 1)'`；antd 經 `ConfigProvider theme.token`，D3 用 `easeCubicOut`，CSS 用 `--motion-dur`／`--motion-ease`；`prefers-reduced-motion` → 0。
- `Progress` 一律 `status="normal"`；`ConfigProvider button={{ autoInsertSpace: false }}`。
- 元件不可定義在其他元件內部；所有輸入都是受控元件。
- i18n：每個新文案在 `zh-TW.ts` 與 `en.ts` 都要有（`MsgKey` 型別會檢查）；core／設定檔的文字照原文顯示。
- 測試：jsdom 只驗 DOM 狀態；動畫在 Task 11 用真實瀏覽器驗證。

## Review Focus

1. 卡數輸入打 0、空白、小數、超過 100,000 → reducer 拒絕，畫面保留上一個合法值並顯示 `count.range` 提示（Task 1 reducer 測試 + Task 4 元件測試 `count input rejects out-of-range values`）。
2. 刪除一列自訂硬體，而它正被展開、有手動卡數、在比較表裡 → `openRow` 變 null、override 移除、`custom:i` 之後的索引一起位移；比較表保留快照不受影響（Task 1 測試 `removing a custom platform reindexes overrides`）。
3. 網址的 `o=` 指向不存在的列、索引超出、`tp` 不合法，或 `x=` 不是合法 base64／JSON／schema → 逐項丟掉、其他欄位照常（Task 1 測試 `decodeUrl drops bad overrides and custom entries`）。
4. 調整過卡數的列放不下模型（`usage === null`）時展開 → 試算區只顯示原因與建議動作，不畫曲線、不崩潰（Task 5 測試 `workbench without usage shows only the reason`）。
5. HF 匯入時離線、401、404、無法解析 → Drawer 內顯示對應訊息（401 時出現 token 欄位），目前模型不變（Task 9 測試）。
