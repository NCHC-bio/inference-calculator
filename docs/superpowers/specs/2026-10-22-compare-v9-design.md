# 網站 v9：方案比較圖表（設計文件）

日期：2026-10-22。補充 `2026-10-21-direct-manipulation-design.md`（下稱「v8 設計」），取代其中「方案比較」的部分（§2 表格「比較」列、§3.1「加入比較」、§4 第 6 項、§7 `pins`）。主設計與 v8 設計的其他規則（資料誠信、元件庫、動畫、RWD、hover popover）全部繼續適用。

**視覺規格**：`docs/prototypes/calculator-demo-v9.html`（使用者 2026-10-22 核可）。demo 的數字是假的；版面、文案、互動與動畫以 demo 為準，數字一律來自 core。

## 1. 為什麼

v8 的比較只有一張數字表，而且：

- 要比硬體得一列一列展開、按「加入比較」，很繁瑣。
- 只能比平台；「同一台機器跑不同模型」這類問題答不了。
- 沒有圖，使用者要自己在 TPS、TTFT、上限三欄之間拼出答案。

國網同時服務「已經有機器、要選模型」和「要採購機器」兩種人。以三個角色（固定 8 張 H100 選模型的管理者、寫採購提案的系所、只有一台 DGX Spark 做長文件 RAG 的研究者）模擬走過後的共識：

- 使用者比較時，問題固定（人數、用途、速度要求），變的是候選方案，而且通常一次只換一項。
- 他們要看的是「每個方案對我的需求過不過關、餘裕多少」，不是並排的數字。
- 選模型的人主要看「人數 → 每人速度」；長文件用途先卡在首字等待；只有採購的人用「卡數 → 速度」。
- 每條線都要有明確結論：不達標要寫出來（不是「最多 0 人」），放不下要明說，用到推估值的線要在線上看得出來。
- 只看速度時小模型永遠贏，要附模型大小。

## 2. 目標與非目標

目標：

- 一步加入比較；同機台換模型、精度、用途、讀入長度、數量都能比。
- 比較即時跟著句子：改人數、速度要求，所有線一起動（不是凍結的快照）。
- 用圖回答「誰過關、到幾人為止、多買卡有沒有用」，表格當摘要。

非目標：

- 費用：config 沒有價格資料，依資料誠信規則不推估。只顯示功耗（kW）。
- benchmark 分數：沒有資料。用模型大小（總參數、MoE 活躍參數）當參考。
- 「把變體套用到所有已選機台」、第二條「明年人數」線：先不做（hover 十字線可讀任意人數）。

## 3. 互動

### 3.1 加入比較

- 每個平台列（含不可行的列與自訂硬體）的右側有 antd `Checkbox`「比較」，不用展開；hover 說明「不用展開，勾選後直接畫進下方的比較圖」（不可行的列：「勾選後在比較裡標出它為什麼不行」）。
- 勾選＝加一條「跟著該列走」的線；取消勾選＝移除那條線。
- 試算區（展開後）不再有「加入比較」按鈕。
- 比較卡片在第一條線加入時淡入展開（`.reveal`），清除最後一條時收合。

### 3.2 換一項比較（變體）

每條線有 `Dropdown`「換一項比較」，子選單（antd menu `children`）：

| 子選單 | 選項 | 新線 |
|---|---|---|
| 換模型 | 目錄中其他模型（附模型大小） | 換模型，精度：原精度若該模型提供就保留，否則用該模型第一個選項 |
| 換精度 | 這個模型的其他精度（附說明）；分隔線後「其他精度各加一條」 | 換精度 |
| 換用途 | 其他工作預設 | 換工作（清掉讀入長度） |
| 換每次讀入長度 | 8k／32k／128k token（不同於目前的） | 以目前工作為基礎的自訂工作，只改 inputTokens |
| 換數量 | 一半（「預算減半」）、加一個 node（Mac：加一台）、兩倍 | 換數量 |
| 換機台 | 其他平台（附該列目前數量） | 換平台，數量跟著新列走 |

- 換模型／精度／用途／讀入長度時，新線**固定為原線目前的數量**（同機台同卡數比較）。
- 最多 5 條線（配色上限，見 §4.3）。已滿時按鈕停用，hover 說明「最多 5 條線，先刪掉一條」；「各加一條」超過時只加前幾條並提示。
- 每條線有刪除鈕（`DeleteOutlined`）；卡片右上「清除」。

### 3.3 線的資料模型

一條線只存「換掉了什麼」，其餘跟句子與平台列走：

```ts
type CompareLine = {
  id: number;
  slot: 0 | 1 | 2 | 3 | 4;   // 顏色與字母 A–E；建立時取最小的空位，刪掉別條不會變
  row: RowKey;               // 平台列
  model?: string;            // 目錄模型 id；沒有＝句子的模型（含自訂模型）
  quant?: string;
  workload?: string;         // 工作預設 id
  inputTokens?: number;      // 讀入長度（以 workload 或句子的工作為基礎）
  gpus?: number;             // 數量；沒有＝該列目前的數量（建議或使用者設定）
};
```

- 「跟著該列走」的線＝只有 `row` 的線；列上的勾選框狀態就是「有沒有這種線」。
- 不可行的列沒有建議數量：GPU 平台用一個 node 的卡數，Mac 用 1 台（**設計者判斷**：讓比較顯示它為什麼不行）。
- 句子改變時，v8 的規則照舊清掉各列的使用者數量；線上有 `gpus` 的保留。
- 線指到的精度若對該模型不合法（例如句子換了模型），改用該模型的第一個選項。
- 刪除自訂硬體時，指到它的線一起刪，後面的 `custom:i` 往前移（與 overrides 相同的規則）。
- 比較線進網址（`cmp=`，base64url JSON，載入時逐項驗證，不合法的丟掉）。v8 不放進網址是因為它是快照；v9 的線是設定，分享給委員會要能帶著走（**設計者判斷**）。

## 4. 畫面

### 4.1 卡片頂端

一行說明（`Text type="secondary"`）：「所有方案回答同一題：同時 N 人、每人至少 X 字/秒、首字 Y 秒內。加粗的欄位是這條線換掉的，其餘跟上方句子一致。虛線＝用到推估值。」

### 4.2 摘要

- 容器寬 ≥ 640 px：antd `Table`（`scroll={{ x: 'max-content' }}`，只在表格內捲動）。欄：方案｜結論｜每人速度｜首字｜最多人數｜模型大小｜功耗｜動作。
- 容器寬 < 640 px：每條線一張小卡（左邊 4 px 線色、結論、指標換行排列、動作）。
- **方案**：線樣（顏色、推估時虛線）＋字母；第一行「平台 sub × 數量」，第二行「模型・精度（・用途・讀入 32k）」，被換掉的欄位加粗；`推估`、`自訂` Tag。
- **結論**：`達標`（success，`CheckCircleOutlined`）／`不達標：原因`（error，hover 顯示 core 的 detail）／`放不下`（default，hover 顯示 detail）。
- 最多人數：不達標且 0 人時顯示「達不到」（error 色）。數字以 motion token tween，單位寫在格子裡且不換行。
- 模型大小：`70B`；MoE `117B（每字只用 5.1B）`；hover「參數越多通常能力越強；MoE 模型每個字只用一部分參數，所以較快」。
- 功耗：`1.4 kW`，未知時「未查證」＋ hover core 的 powerNote。
- 摘要下方一行提示：「想加方案：在平台列勾「比較」，或按「換一項比較」複製一條線、只改一項（數量不變）。」
- 有任一線的 warnings：去重後列在卡片底部（沿用 v8）。

### 4.3 圖表（不切換，摘要下方）

寬螢幕兩欄（人數→速度｜人數→首字），下方整列（卡數→速度）；窄螢幕全部堆疊。

1. **人數 → 每人速度**（標題旁：「綠色區＝達標（X 字/秒以上）」）
2. **人數 → 首字等待**（「綠色區＝達標（Y 秒內）」）
   - 兩張共用 x 軸：同時在線人數，對數刻度（1、2、5、10…；寬 < 380 px 只標 10 的次方），範圍 1 … max(10, 人數 × 3, 各線上限 × 1.6)。
   - 每條線＝core 在這些人數的點；記憶體放不下（why = mem／context）之後線結束。
   - 達標區塗 `colorSuccessBg`，目標為虛線（`colorSuccess`）。
   - 「你的 N 人」垂直虛線（`colorText`）；每條線在 N 的位置一個圓點（線色、2 px 背景色描邊）。
   - 速度圖：每條線在上限處一個空心圓與「最多 N」；與前一個標籤相距 < 64 px 或太靠右時只留圓點（數字在表格）。
   - 線尾字母（`colorText`），依高度排開至少 12 px。
   - 共用 hover 十字線：滑鼠移動／觸控點擊，兩張圖同時顯示同一人數；提示框（`colorBgElevated`）列出每條線在該人數的值，夾在圖內不溢出。
   - 多數方案卡在哪個指標（core why：ttft 對 bw／compute），那張圖標題旁加紅 Tag「N 個方案卡在這」。
3. **GPU 張數 → 每人速度**（「在你的 N 人下・圓點＝目前張數・線變平＝再加卡也不會更快」）
   - 只在 GPU 線中有 ≥ 2 種（平台, 數量）時出現（`.reveal`）。
   - x：GPU 張數（線性），1 … max(8, 各線數量 × 2)；每條 GPU 線用 core 的 sweep（每個數量最快且達標的切法，否則預設切法），放不下的數量不畫。
   - 以台計的平台不放進來，下方註明「D 以「台」計，和 GPU 張數單位不同，不放進這張圖。」
- 放不下的線沒有曲線，卡片底部註明「E 放不下，圖上沒有線」。

配色（資料視覺化規範的已驗證類別色前 5 個；淺色／深色各一組，跟著 `prefers-color-scheme`）：

| slot | 字母 | 淺色 | 深色 |
|---|---|---|---|
| 0 | A | `#2a78d6` | `#3987e5` |
| 1 | B | `#eb6834` | `#d95926` |
| 2 | C | `#1baf7a` | `#199e70` |
| 3 | D | `#eda100` | `#c98500` |
| 4 | E | `#e87ba4` | `#d55181` |

顏色不是唯一辨識：字母直接標在線上，表格有線樣；推估線為虛線（`6 4`）＋表格 `推估` Tag。

### 4.4 動畫

沿用 v8 的 motion token（400 ms、ease-out cubic，reduced motion → 0）：

- 卡片與卡數圖用 `.reveal` 展開／收合；新線淡入、刪除的線淡出。
- 人數或條件改變：路徑、圓點、「你的 N 人」線、標籤與 y 軸刻度同時過渡（D3 transition，與 SpeedChart 相同的 `keyed`／`moving`／`translate`）；表格數字 tween。
- hover 十字線與提示框不需過渡（跟手）。

## 5. core 新增

`estimatePerformance` 加選填 `curveUsers: number[]`（1–64 個嚴格遞增的正整數，≤ MAX_N）。有 `usage` 時，`speedCurve` 改在這些人數取點（不受 maxConcurrent 限制，每點帶 core 的 why）；沒給時行為不變。公式仍只在 solve.ts（`shapeProfile` 接受明確的人數清單）。網站不自己算任何點。

## 6. 移除

- `Pin` 型別、`pin`／`unpin`／`clearPins` action、`PINS_MAX`、試算區「加入比較」按鈕與 `CompareTable`。
- 對應的 i18n 鍵與測試改寫成比較線版本。

## 7. 驗證

- 單元：reducer（加／刪／切換／上限／slot 重用／刪自訂硬體時位移／句子改變時保留 gpus／精度合法化）、網址往返、線 → core 輸入的對應（每個數字等於直接呼叫 core）、變體選單項目、結論與「達不到」。
- core：`curveUsers` 的點等於逐一 checkShape；不給時輸出不變。
- e2e（Playwright，真實瀏覽器）：勾選列、換一項比較（含「各加一條」與上限提示）、刪除、清除；390／768／1024／1440 × 淺色／深色無水平捲動；人數改變時路徑、圓點、參考線逐格過渡、reduced motion 直接到終點；console 無錯誤；各狀態截圖（5 條線、不達標、放不下、卡數圖出現／消失、手機卡片）。

## 8. 使用者決定紀錄（2026-10-22）

- 比較要「疊圖」呈現，不要切換；加入比較要一步完成；同機台不同模型要能比。
- 以使用者角度（模擬三種角色）決定圖表，而不是問開發者。
- 試算區內的「加入比較」移除，只留平台列上的勾選。
- demo v9 核可後開 dev branch 實作；正式版要檢查 UX 與不同寬度顯示。

## 9. 實作時的決定（2026-10-22）

- **C1** 推估線的虛線只在「有些方案用推估、有些沒有」時使用；目前幾乎所有結果都用到推估值，全部畫虛線會失去區分又難讀，所以全部是推估時畫實線，卡片說明寫「全部方案都用到推估值（表格標「推估」）」，每條線仍標 `推估`（主設計 §2.1）。
- **C2** 寬表格放不進 980 px 的卡片：「換一項比較」與刪除移到方案欄第三行（與窄卡片相同），方案欄最寬 280 px，表頭可換行；卡片寬 < 880 px 改用每線一張卡（原定 640 px）。
- **C3** 「換一項比較」子選單點擊展開（`triggerSubMenuAction: 'click'`），觸控也能用。
- **C4** 線尾字母只在水平 14 px 內才互相錯開，就近找空位，不出圖表範圍；提示框放在圖內 30 px 處，不擋「你的 N 人」。
- **C5** 「其他精度各加一條」只在其他精度 ≥ 2 個時出現。
- **C6** 讀入長度超過模型上限時，core 回傳 why = context，該線顯示「放不下」與 core 的說明（不是錯誤畫面）。
